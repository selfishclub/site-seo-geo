# 글 구조 점검 · 기준과 review.json

**왜**: AI는 페이지 전체를 옮기지 않고, 질문에 딱 맞는 한두 문장을 뽑아서 답한다. 그 문장이 찾기 쉬운 자리에 있어야 인용된다.

`outline.mjs`가 뽑은 사실(제목 나무 · 각 칸 첫 문장 · 블록 수 · 글자로 적힌 사실 · 날짜 · 근거)만 근거로 판단한다.

## 점검 항목 8가지

| # | 이름(그대로 쓴다) | 확인할 것 | 왜(그대로 말한다) | ✕ / △ 기준 |
|---|---|---|---|---|
| 1 | 첫 화면 한 문장 | H1이나 그 바로 아래에 「누가 · 누구에게 · 무엇을」이 한 문장으로 있나 | AI가 「이 사이트는 뭐야?」에 답할 때 쓰는 문장이에요 | ✕ 없음 · △ 셋 중 하나 빠짐 |
| 2 | 손님 질문 모양 제목 | H2가 「About · Services」 같은 이름표가 아니라 손님이 묻는 말인가 | 사람들이 AI에 묻는 말과 맞아야 내 글이 찾아져요 | △ 이름표만 있음 |
| 3 | 첫 문장에 바로 답 | 각 H2 아래 첫 1~2문장이 그 제목에 바로 답하나 | 서론이 길면 AI가 답을 못 찾아요 | △ 인사 · 감성 문구로 시작 |
| 4 | 사실은 글자로 | 가격 · 시간 · 지역 · 연락처가 글자로 있나(outline facts) | 이미지 속 글자는 AI가 못 읽어요 | ✕ 연락처 없음 · △ 일부 없음 |
| 5 | 정리된 모양 | 비교는 표, 순서는 번호, 자주 묻는 질문은 FAQ | 정리된 모양일수록 뽑아 쓰기 쉬워요 | △ 해당 내용이 있는데 줄글뿐 |
| 6 | 경험 · 숫자 · 출처 | 직접 해 본 과정, 결과 숫자, 후기, 출처 링크 | 네이버 · 구글 모두 「직접 해 본 이야기」를 앞에 세워요. 출처와 통계를 넣으면 AI 답변 노출이 30~40% 늘었다는 연구도 있어요 | △ 숫자 · 사례 없음 |
| 7 | 날짜 · 누가 썼나 | 업데이트 날짜, 소개/운영자 칸 | 최신이고 믿을 만한 정보인지 판단하는 근거예요 | △ 둘 다 없음 |
| 8 | 어디서나 같은 소개 | 이름 · 한 줄 소개가 SNS 프로필 · 지도 · 블로그와 같은 말인가 | 여러 곳에서 같은 말이 나와야 AI가 사실로 믿어요 | 사용자에게 SNS 소개를 물어 비교, 모르면 「확인해 보세요」로 둔다 |

## 추천 구조 만들기

사이트 종류에 맞는 순서를 기본으로 하되, **사이트에 이미 있는 내용으로만** 칸을 채운다. 없는 칸은 `note`에 「✎ 채울 것」이라고 적는다.

| 사이트 종류 | 추천 H2 순서 |
|---|---|
| 개인 소개 · 포트폴리오 | 어떤 일을 하나요? → 해 온 일(사례) → 이렇게 일해요 → 자주 묻는 질문 → 연락 방법 |
| 가게 · 서비스 | 어떤 곳인가요? → 메뉴/서비스와 가격 → 이용 방법 · 시간 · 위치 → 손님 후기 → 자주 묻는 질문 → 예약 · 연락 |
| 교육 · 강의 · 모임 | 어떤 과정인가요? → 이런 분께 맞아요 → 커리큘럼 → 일정 · 가격 · 장소 → 수강생 결과 · 후기 → 자주 묻는 질문 → 신청 |
| 제품 · 앱 | 무엇을 해 주나요? → 이렇게 써요(단계) → 다른 방법과 비교(표) → 가격 → 자주 묻는 질문 → 시작하기 |

- H1: 「누가 · 누구에게 · 무엇을」 한 문장. 예: 「소상공인에게 AI 마케팅을 가르치는 ○○」
- 질문 모양 H2는 사람이 실제로 말하는 문장으로 쓴다(「가격은 얼마인가요?」).
- **자주 묻는 질문**은 「전화나 DM으로 가장 많이 받는 질문」을 사용자에게 3~5개 물어서 만든다. 답은 사용자가 말한 사실로만 쓴다.

## review.json 형식
```json
{
  "summary": "한두 문장 총평(쉬운 말)",
  "pages": [
    {
      "url": "https://…/",
      "recommended": [
        { "level": 1, "text": "소상공인에게 AI 마케팅을 가르치는 ○○", "note": "누가·누구에게·무엇을" },
        { "level": 2, "text": "어떤 교육인가요?", "note": "질문 모양, 첫 문장이 바로 답" },
        { "level": 2, "text": "수강생 결과", "note": "✎ 채울 것: 결과 숫자 · 후기" }
      ],
      "items": [
        { "name": "첫 화면 한 문장", "grade": "fail", "why": "…", "now": "지금 H1: 「Welcome」", "fix": "H1을 「…」로" }
      ]
    }
  ],
  "todo": ["✎ 수강생 결과 숫자(예: 누적 수강생 수)", "✎ 연락처를 글자로"]
}
```
- `grade`: pass · warn · fail
- `items`는 위 8가지 이름을 그대로 쓴다. 해당 없으면 빼도 된다.
- 리포트에서 「지금」 구조는 outline.json으로 자동으로 그려지므로 `recommended`만 쓴다.
